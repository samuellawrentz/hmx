hmm / multi-map TUI

Base: h-m-m (PHP, 3854 lines, one file). Add: map list, cross-map links, extract-to-map, large nodes. Sync stays git.

Review round 1 (codex gpt-5.6 + cursor grok-4.5 + me), 2026-09-13: what changed
  • Body lines get a > sigil. Both flagged the 2-space encoding; verified in upstream parser (tabs → 2 spaces before depth).
  • Enter: acts on the link if present, else new sibling. Cursor wanted Enter = sibling only, codex wanted Enter = follow. Merged, no muscle-memory break.
  • Missing link target: confirm before create (both).
  • Map rename rewrites inbound links across maps (codex). Node-title links: exact → substring → root + message.
  • List / falls back to content grep (codex). Cursor said grep is enough; ~5 lines, taken.
  • Dropped v (pane auto-shows) and x export (cursor). Restored P paste-as-siblings (codex). 24 → 23 keys.
  • Extract: one key for filename, link, root title; never overwrite (codex).
  • Taskwarrior split into read-only stage A, mutations stage B (codex wanted a full cut, cursor a defer).
  • Rejected: sidecar body files (both), merge-back (all three), recent screen (all three), ids (FINAL).

1. Large nodes

Today: title is wordwrapped at max_leaf_node_width (55) into a multi-line box. Works to ~4 lines, then the layout gets tall and the tree becomes unreadable.

Decision: a node is title + optional body. Tree renders title only (1–2 wrapped lines, … when body exists). Body shows in a bottom pane automatically when the active node has one, edited in $EDITOR. Never draw the body in the tree. No toggle key.

Body lines carry a > sigil in the file (see §5). Verified: upstream list_to_map rewrites every tab to two spaces before computing depth, so "indent + 2 spaces" would parse as a child. A sigil makes it unambiguous for both parsers.

Ladder check: body-in-editor beats writing an in-TUI text editor. tmmpr wrote one (modal vim clone). Skip it, $EDITOR already exists.

One map in memory at a time. Switching = save-if-modified, reset, load_file. No tabs, no multi-buffer.

5. File format

auth
	Tokens
		JWT rotation
		> Rotate every 24h. Old key stays valid 1h.     ← body: same indent as node, "> " sigil
		> See [[security]].                              ← multiple body lines allowed
		refresh
	[[infra#redis]]
  • Node line = tabs then title. Body line = same tabs then > . Tabs are the only structural indent; normalised on save. Upstream h-m-m shows body lines as children titled > …, harmless and reversible.
  • Link = [[name]] or [[name#node title]]. Plain text, git-diffable, greppable.
  • No index, no ids, no frontmatter. Backlinks = grep -l '\[\[name' *.hmm on demand.

8. Taskwarrior link (later, two stages)

Decision: same [[..]] mechanism, no new data model. A node links to a task by uuid prefix; the task links back with one annotation. hmm never owns task state, it reads it at map open.
Stage A (read-only): render ☐/☑ for [[task:uuid8]] + Enter → task info. Zero writes, zero keys.
Stage B (only if A is used daily): t picker/create, T done.
 ┌ backend ┐
 │         ├── Sessions
 │         │    ├── ☐ Redis eviction policy [[task:4e09cee2]]  due fri
 │         │    └── ☑ TTL config [[task:9b1f00aa]]
 │         └── [[infra#redis]]
 └─────────┘
 t link/create task · T done · Enter on [[task:..]] → task info
piecehow
filetitle line carries [[task:<uuid8>]]. Plain text, greppable: grep -l 'task:4e09' *.hmm
readon map open, collect uuids from titles, one call: task rc.context=none <uuid> <uuid> … export → {uuid: {status, due, owner}}. 35 tasks, ~50 ms. No polling, no cache file.
renderprefix ☐ pending / ☑ completed / ☐ red when due < now. Status only, never the description, the node title already is one.
tnode has no link → picker (the list screen reused) over task rc.context=none status:pending export, sorted by urgency, rows project · due · description, / filters.
Enter on a row → link: node title becomes the task description, [[task:uuid8]] appended, task gets annotate -- "map: backend#Sessions".
n in the picker → new task from the node title: task add "<title>" project:<map name if pod> owner:me, then the same link step. Exact command shown before running.
Esc cancels.
node has link → task <uuid> info in a pager
Ttask <uuid> done, re-read. Undo = task undo, not hmm's undo stack
Enteron [[task:..]] → task info. Same rule as map links: Enter acts on the link
back-linkannotation map: <map>#<node> on the task. Visible in twt I / A. If the node is renamed, the annotation goes stale. Accept it, the uuid in the map is the source of truth
writesalways rc.confirmation=off rc.bulk=0 rc.verbose=nothing, uuid never id. The on-exit hook syncs, hmm does nothing extra

Title rule: the task description wins on link. Task is the source of truth; a node and its task disagreeing is worse than losing a draft title.

Adds 2 keys (t, T) → 26. Skipped: fzf (list screen already exists), pre-filling the picker filter with the node title, linking completed tasks, project/owner/due pickers (use twt), timew start from a node, showing worked time in the tree, a task → map jump from twt (the annotation is the jump, open the map by hand). Add any of these once linking is in daily use.

9. Not building

  • Graph model / node ids across maps. #title suffix covers node-to-node. Add ids when a title collision actually bites.
  • Backlink panel, tabs, splits, search across maps (grep + list filter cover it).
  • In-TUI multiline editor. $EDITOR.
  • Sync. git.
  • Merge-back after extract. Manual path is free: open child, y root, Backspace, p, delete the link node.
  • Recent / jump screen. mtime sort is recency.
  • Inbox as a feature. inbox.hmm is a convention, pinned first in the list.
  • Any-node-to-any-node arrows drawn in the tree. That is tmmpr's problem space, and it breaks the tree layout. Links stay textual.
